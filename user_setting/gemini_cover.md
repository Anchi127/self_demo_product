# V2版本

## Project 成员邀请与管理功能需求文档 (PRD)

### 1. 产品背景

企业在使用 Project 时需邀请不同职能成员（Owner、管理员、财务、成员）协作。系统需支持：

- Owner/管理员邀请新老用户加入并预分配权限。
- 支持定向邀请（指定账号），确保安全性。
- 支持对已入组的存量用户进行角色变更及资产权限调整。
- 流程需兼容未注册、已注册、登录态不匹配等多种账号状态。

### 2. 用户角色定义

| 角色 | 描述 | 权限概要 |
|------|------|----------|
| 项目负责人 (Owner) | 项目最高权限者 | 拥有所有权限；可转移 Ownership；不可删除项目（需平台侧操作）。 |
| 管理员 (Admin) | 项目运营管理者 | 可邀请/移除成员；可配置资产；可设置除 Owner 外的角色。 |
| 财务 (Finance) | 财务专员 | 仅可见财务类菜单/数据；不可操作广告投放；不可邀请/管理成员。 |
| 成员 (Member) | 普通执行人员 | 仅拥有被分配的资产权限；不可邀请/管理成员；不可查看财务数据。 |

### 3. 术语定义

| 名称 | 说明 |
|------|------|
| 定向邀请 | 邀请时系统锁定目标手机号或邮箱，仅该指定账号可验证并接受邀请。 |
| 邀请记录 (Invitation Record) | 系统生成的实体数据，包含受邀者ID、预设角色、预设资产权限、过期时间、Token。 |
| 预分配资产 | 在发出邀请时提前配置的资产权限，用户接受邀请加入项目后立即生效。 |

### 4. 核心业务流程

#### 4.1 发起邀请（Owner/管理员端）

**前置条件：** 用户拥有邀请权限。  
**操作路径：** 成员管理列表页 -> 点击「邀请成员」。

**Step 1：输入邀请信息**  
弹窗包含以下字段：

- **邀请方式（必填）：** 定向邀请

- **邀请账号（必填）：**
  - 输入框支持输入手机号或邮箱。
  - 支持批量输入（UI交互建议：回车生成标签，或多行输入），单次限制最多 N 个（建议 20）。
  - **校验逻辑：**
    - 格式校验：必须为合法的手机号或邮箱格式。
    - 重复校验：自动过滤已在当前项目中的账号。
    - 系统查询 User 表：标记为 Existing User (已存在) 或 New User (不存在)，仅后端标识，前端无感知。

- **设置角色（必填）：**
  - 下拉单选：管理员 / 财务 / 成员。

- **配置资产（选填）：**
  - 前提：当角色选择"管理员"或"成员"时显示；若选择"财务"则隐藏（财务默认无资产权限或由系统定义）。
  - 展示形式：分组列表（按媒体或资产类型），支持多选。

**Step 2：生成邀请**  
点击「生成邀请链接」按钮：

- 系统为每一个输入的账号生成一条独立的 Invitation Record。

- **数据结构：**

```json
{
  "project_id": "xxx",
  "inviter_user_id": "xxx",
  "invited_identifier": "手机号或邮箱",
  "invited_role": "admin/finance/member",
  "invited_assets": ["asset_id_1", "asset_id_2"],
  "expires_at": "当前时间 + 7天",
  "status": "pending",
  "token": "Unique_Token_String"
}
```

- **UI 反馈：**
  - **单人邀请场景：**
    - 直接展示该用户的邀请链接。
    - 提供「复制链接」按钮。
  - **多人批量邀请场景：**
    - 展示生成结果列表，列表包含：受邀账号、预设角色、专属邀请链接。
    - **操作交互：**
      - 单个复制：列表每一行末尾提供「复制链接」按钮，点击仅复制该行的链接。
      - 一键复制全部：列表顶部或底部提供「复制全部链接」按钮。
      - 点击效果：将所有账号及对应的链接格式化复制到剪贴板，便于管理员分发。

- **复制格式示例：**

```
张三 (13900001111): https://.../invite?token=ABC
李四 (lisi@example.com): https://.../invite?token=XYZ
```

#### 4.2 落地页（邀请入口页）逻辑

**前置条件：** 用户访问链接 `/invite?token=XXXXX`。

**系统初始化判断：**

- 校验 Token 有效性（是否存在、是否过期、是否已使用）。
- 若无效/过期：显示错误页，提示"链接已失效或不存在"。
- 解析 Token 获取 invited_identifier (受邀账号)、project_info、enterprise_info。

**判断当前浏览器登录状态：**

##### 场景 A：用户未登录

**UI 展示：**

- **邀请提示卡片：**
  - 标题：邀请加入 [企业名称] - [项目名称]
  - 角色：[预设角色]
  - 提示文案：您是否确认以 [受邀手机/邮箱掩码，如 139****1234] 的身份加入？请输入完整账号进行验证。

- **账号验证区：**
  - 输入框：请输入完整手机号/邮箱。
  - 按钮：「下一步」。

**交互逻辑：**

- 用户输入账号 -> 点击下一步。
- 匹配校验：判断输入账号是否与 invited_identifier 一致。
- 不一致：提示错误"输入账号与受邀账号不匹配，请重新输入"。
- 一致：进入 场景 C (身份验证)。

##### 场景 B：用户已登录

- **匹配校验：** 判断 当前登录账号 是否等于 invited_identifier。

- **匹配 (Yes)：**
  - UI 展示邀请提示卡片（同上）。
  - 按钮：「确认加入」。
  - 点击后直接完成加入流程。

- **不匹配 (No)：**
  - 弹窗/全屏提示："此邀请函仅限 [受邀账号掩码] 使用，您当前登录的是 [当前账号]。"
  - 操作选项：提供「切换账号」按钮，点击后退出登录，跳转至 场景 A。

##### 场景 C：身份验证（针对未登录且账号匹配成功的情况）

根据系统查询 User 表的结果区分流程：

- **情况 C-1：账号已存在 (Existing User)**
  - UI 展示：密码输入框。
  - 操作：输入密码 -> 登录 -> 校验通过 -> 自动加入项目 -> 跳转至成功页。
  - 异常处理：若忘记密码，提供"忘记密码"跳转，重置后需重新访问链接。

- **情况 C-2：账号不存在 (New User)**
  - UI 展示：注册表单。
  - **字段：**
    - 姓名 (必填)
    - 职位 (选填)
    - 验证码 (必填)：触发发送短信/邮件验证码（安全必要项，防止冒充）。
    - 设置密码 (必填)
    - 确认密码 (必填)
  - 操作：提交注册 -> 系统创建账号 -> 登录成功 -> 自动加入项目 -> 跳转至成功页。

#### 4.3 加入成功后

- 更新 Invitation Record 状态为 accepted。
- 在 Project Member 表中写入成员数据。
- 根据 invited_role 和 invited_assets 写入权限表。
- 页面跳转至 Project 首页或个人信息页，并Toast提示"加入成功"。

### 5. 成员与权限管理

#### 5.1 修改成员角色及权限

**前置条件：** 操作者为 Owner 或 管理员。  
**入口：** 成员管理列表 -> 操作列 -> 「编辑」。

**UI/交互逻辑：**

- 打开「编辑成员」抽屉/弹窗。
- **基本信息区（只读）：** 展示姓名、账号、加入时间。
- **角色设置：**
  - 下拉框回显当前角色。
  - 允许修改（规则：管理员不可修改 Owner 角色，管理员不可将他人修改为 Owner）。
- **资产配置：**
  - **逻辑关联：**
    - 若角色修改为"财务"，资产配置区域隐藏或置灰（不可选）。
    - 若角色为"管理员/成员"，展示资产选择树/列表。
  - 回显：默认勾选该成员当前已拥有的资产。
  - 操作：支持增加勾选或取消勾选。
- **提交保存：**
  - 后端更新用户在当前项目下的角色字段。
  - 后端全量更新该用户的资产关联数据（增量添加新资产，移除取消勾选的资产）。

#### 5.2 移除成员

- Owner 可移除 管理员、财务、成员。
- 管理员 可移除 财务、成员。
- 移除后，该成员在该项目下的所有资产权限立即失效，Token 强制失效。

#### 5.3 待接受邀请管理

在成员管理页增加「待接受邀请」Tab 或 列表区域：

- **字段：** 受邀账号、邀请人、邀请时间、状态（待接受/已过期）、操作。
- **操作：**
  - 复制链接：再次获取邀请链接。
  - 撤回邀请：点击后，该条 Invitation Record 状态变更为 revoked，链接立即失效。
  - 重新发送：仅针对"已过期"状态，点击后生成新的 Token 和过期时间，旧链接依旧失效，生成新链接。

### 6. 权限矩阵规则

| 行为操作 | Owner (负责人) | Admin (管理员) | Finance (财务) | Member (成员) |
|----------|----------------|----------------|----------------|---------------|
| 邀请成员 | ✔ | ✔ | ✘ | ✘ |
| 编辑成员角色/资产 | ✔ | ✔ (无法编辑 Owner) | ✘ | ✘ |
| 移除成员 | ✔ | ✔ (无法移除 Owner/其他Admin) | ✘ | ✘ |
| 转移 Owner | ✔ | ✘ | ✘ | ✘ |
| 项目归档/删除 | ✘ (仅平台侧) | ✘ | ✘ | ✘ |
| 查看资产数据 | 全部 | 全部 | ✘ | 仅限分配的资产 |

### 7. 异常场景与边界条件

| 场景 | 预期系统行为 |
|------|--------------|
| Token 过期 | 落地页提示"邀请链接已过期，请联系管理员重新邀请"。 |
| Token 无效/被篡改 | 落地页提示"无效的邀请链接"。 |
| 邀请被撤回 | 用户访问链接时，提示"该邀请已被撤回"。 |
| 资产已被删除 | 若预分配的资产在用户加入前被删除，用户加入通过，但日志记录"部分资产授权失败：资产不存在"，不阻断加入流程。 |
| 项目被冻结/归档 | 落地页提示"项目状态异常，无法加入"。 |
| 当前登录账号非受邀账号 | 拦截，强制要求切换账号（详见 4.2 场景 B）。 |
| 账号已被平台封禁 | 在登录或注册提交时，提示"账号状态异常，请联系客服"，阻断流程。 |
| 用户已在项目中 | 若用户点击链接，但已经是项目成员：直接跳转至项目首页，Toast提示"您已是该项目成员"。 |

# V1版本

## 1. 产品背景

企业在使用 Project 时，需要邀请成员协作，包括 Owner、管理员、财务、成员。为提升协作效率，需要满足：

- Owner/管理员可邀请新成员加入 project
- 邀请可同时设置角色和预分配资产
- 未注册用户可通过邀请完成注册并入组
- 已注册用户可直接接受邀请
- 系统自动兼容账号状态（已登录/未登录/登录用户与邀请账号不一致）
- Owner 可转移但不可删除 Project
- 平台侧可在必要时协助转移 Owner

## 2. 用户角色

| 角色 | 描述 |
|------|--------|
| 项目负责人 | Project 的最高权限者，可转移 ownership 但不可删除项目 |
| 管理员 | 可邀请成员、配置项目资产、设置角色 |
| 财务 | 仅查看财务类菜单，无法邀请 |
| 成员 | 使用非财务、非权限管理类功能，资产数据权限有管理员或项目负责人分配，不可邀请 |

## 3. 术语定义

| 名称 | 说明 |
|------|--------|
| 定向邀请 | 邀请时必须指定手机号或邮箱，只有该账号才能接受邀请 |
| 邀请记录（Invitation Record） | 系统内用于记录被邀请者信息、预设角色和资产的实体 |
| 预分配资产 | 邀请时提前给被邀请者配置可访问资产，加入即生效 |

## 4. 核心流程（流程图式拆解）

### 4.1 发起邀请（Owner/管理员端）

**Step 1：打开「邀请成员」弹窗**

包含如下区域：

**A. 邀请方式（定向邀请）**

- 输入邀请目标：
  - 手机号
  - 或 邮箱
  - 可输入多个，但只支持一种类型的批量，即多个手机号或多个邮箱

- 系统逐一执行查重：
  - 查找 user 表：
    - 存在 → Existing User
    - 不存在 → New User

**B. 设置角色**

下拉框（单选）：

- 管理员
- 财务
- 成员

**C. 配置资产（可多选）**

展示该项目内可配置资产（按媒体或资产类型分组）：

- 广告账户
- 素材分析报告
- 素材

UI：多选列表

**D. 确认生成邀请链接**

点击「生成邀请链接」 → 生成邀请链接，需要有以下数据：

```
Invitation Record {
  project_id,
  inviter_user_id,
  invited_identifier (手机号或邮箱),
  invited_role,
  invited_assets: [asset_ids],
  expires_at (默认 7 天)（ui上也需要提示有效期，仅提示）,
  status: pending,
  token: 随机生成
}
```

**系统动作：**

- 生成邀请链接，带有一键复制功能

### 4.2 被邀请者点击邀请链接

- **邀请链接格式：** `/invite?token=XXXXX`
- 系统取 token → 查询 Invitation Record。

**记录包含：**

- invited_identifier（手机号或邮箱）
- invited_role
- invited_assets
- project_id
- enterprise_id（如 Project 从属于企业）
- 项目 & 企业展示名称

进入落地页后进入登录/注册判断流程。

### 4.3 落地页（邀请入口页）逻辑

当用户通过邀请链接打开邀请入口页时：

**系统判断流程**

**① 判断是否登录**

- **已登陆** -> 判断当前登录账号是否匹配被邀请手机号/邮箱
  - **Y -> 匹配** → UI 上展示邀请提示模块，提示用户确认加入信息后，用户确认即加入项目
  - **N -> 不匹配** → 弹框提示「此邀请仅限 xxx 手机号/邮箱使用」（手机/邮箱需加密展示） → 提供退出重新登录入口"不是（手机/邮箱需加密展示）？切换账号"

- **未登录** → UI 上展示邀请提示模块，引导用户输入完整受邀号码后校验登陆或注册

**② 邀请入口页（3种状态）**

**（A）邀请提示模块（填写账号前即可看到）**

- 整块局中靠上，颜色轻微高亮，保证用户知道这是"受邀加入"流程
- **内容：**
  - 你正在加入企业：XXXX公司
  - 即将加入项目：XXXX Project
  - 你的角色：管理员
  - 项目初始权限：X 项资产即将授予
  - "您是否确认以 139****1234 的身份加入？请输入完整手机号/邮箱继续。"（根据邀请的是邮箱还是手机号来分别展示）

**（B）账号输入区**

- 输入框，框内提示展示：请输入受邀完整手机号/邮箱
- 按钮，"继续"

**流程：**

- 用户输入账号 → 点击 "继续"
- 判断当前输入账号是否匹配被邀请手机号/邮箱
  - **Y -> 匹配** -> 校验新用户或存量用户 -> 进入邀请登陆流程或注册
  - **N -> 不匹配** -> 显示错误提示："与受邀手机号/邮箱不匹配，请重新输入"

**（C）信息校验一致下的邀请登陆或注册**

**流程：**

- 校验当前输入账号是否已注册
  - **Y -> 已注册** -> 展示密码输入框，输入后登陆 -> 登录成功 → 自动加入项目 → 显示成功页
  - **N -> 未注册** -> 展示密码、确认密码、姓名、职位，填写提交后完成注册 -> 登录成功 → 自动加入项目 → 显示成功页

### 4.4 用户接受邀请

当账号与邀请匹配并完成登陆后，跳转至：

- 个人信息页面

并展示「加入成功」提示（按UED规范，右下角提示或中央上方提示）。

## 5. 详细功能需求

### 5.1 发起邀请

| 功能点 | 说明 |
|--------|--------|
| 必须输入手机号/邮箱 | 仅允许邀请指定目标 |
| 系统识别用户存在性 | 用于后续流程跳转 |
| 可设置角色 | 除项目主理人外均可由管理员设置 |
| 可预配置资产 | 预绑定到邀请记录，接受后自动授予 |
| 生成邀请链接 | 包含 token，用于验证 |

### 5.2 接受邀请

| 功能点 | 说明 |
|--------|--------|
| token 校验 | 无效/过期 → 页面提示过期或无效 |
| 引导登录/注册 | 根据账号状态自动跳转 |
| 账号比对 | 确保只有被邀请者才能加入 |
| 自动绑定权限 | 根据邀请记录写入 role + asset |
| 邀请过期 | 允许管理员再待接受邀请列表中重新生成邀请链接 |

### 5.3 管理邀请

在成员管理页展示「待接受邀请列表」

可对 **已过期** 邀请执行：

- 重新发送邀请
- 超过 7 天自动失效

## 6. 权限规则

| 行为 | 负责人 | 管理员 | 财务 | 成员 |
|------|--------|--------|------|------|
| 邀请成员 | ✔ | ✔ | ✘ | ✘ |
| 配置资产 | ✔ | ✔ | ✘ | ✘ |
| 转移负责人 | ✔ | ✘ | ✘ | ✘ |
| 删除成员 | ✔ | ✔ | ✘ | ✘ |
| 项目归档 | ✘（只能平台侧执行） | ✘ | ✘ | ✘ |

## 7. 异常 & 边界情况

| 情况 | 系统行为 |
|------|----------|
| token 无效 | 显示「邀请不存在」 |
| token 过期 | 显示「邀请已过期」并允许发起方重新发送 |

# 会议总结

### 一、 核心矛盾：两种产品哲学的根本性冲突

会议的核心矛盾在于两种截然不同的产品设计哲学之间的碰撞，可以概括为 **“革命 vs. 演进”** 或 **“理想主义 vs. 实用主义”**。

1.  **革命派 (以刁为代表): Agent原生模式**
    *   **理念:** 彻底颠覆传统SaaS交互。**对话就是主界面**，所有的操作和结果（中栏“结果树”、右栏“GUI”）都是由对话驱动和生成的。AI不是助手，而是交互本身。
    *   **关键词:** 领先、创新、虚拟、Agent原生。
    *   **目标:** 创造一种全新的、以自然语言为中心的工作流。

2.  **演进派 (开发与设计团队): SaaS + Copilot模式**
    *   **理念:** 在成熟、稳定的传统SaaS应用基础上，**将AI作为一个强大的“助手”(Copilot)集成进去**，以辅助用户更高效地完成任务。用户仍然拥有熟悉的列表、按钮和表单。
    *   **关键词:** 可行、高效、用户习惯、SaaS最佳实践。
    *   **目标:** 通过AI增强现有SaaS应用的能力，平稳地提升用户体验。

这场会议的本质，就是决定产品未来要走上哪一条道路。

### 二、 会议关键信息与待办

*   **明确了刁的真实设想:** 最重要的信息是，团队确认了刁要的是彻底的“Agent原生”模式，并明确否定了团队倾向的“Copilot”模式（“不是AI帮你点”）。
*   **团队共识明确:** 开发与设计团队内部达成了清晰的共识——他们一致认为“SaaS + Copilot”模式是“最快、最可行、最现阶段最可行的东西”。
*   **核心风险暴露:** 团队向决策者当面指出了“Agent原生”模式的多个根本性问题：
    *   **可用性风险:** 颠覆用户习惯，学习成本极高。
    *   **技术风险:** 状态保持和多任务处理难以实现。
    *   **工程风险:** 缺乏通用性，导致开发成本激增，迭代困难。
*   **导航设计悬而未决:** 整个应用的顶级导航方案（左侧菜单如何展开二级、顶部导航是否存在等）完全没有定论，已成为设计的最大阻塞点。
*   **唯一具体结论:** “企业认证”功能将作为“设置”下的一个可链接的Tab页存在。
*   **待办事项:**
    1.  **（决策）** 必须在两种核心模式之间做出最终选择。
    2.  **（易安琪）** 绘制一份能体现“Agent原生”模式的设计稿，作为下一轮评审的靶子。

### 三、 各方表态与立场

1.  **刁 (决策者 / 理想主义者):**
    *   **立场:** 坚定地推动“Agent原生”的革命性方案。
    *   **表态:** 明确表示不接受Copilot模式，认为自己的设想是更“领先”的。他在乎的是交互范式的创新，可能对团队提出的工程和可用性细节问题尚未给予足够重视。

2.  **开发与设计团队 (执行者 / 实用主义者):**
    *   **立场:** 坚决拥护“SaaS + Copilot”的演进式方案。
    *   **表态:** 他们并非抱怨“路难走”，而是从专业角度判断刁所指的“路”本身“不合理”、“不通”。他们通过反复陈述、举例和质疑，表达了对“Agent原生”模式在可用性、稳定性和工程可行性上的深切忧虑。

3.  **易安琪 (设计者 / 调和者):**
    *   **立场:** 试图理解并翻译决策者的抽象理念，并将其具体化为可供讨论的设计方案。
    *   **表态:** 她承担了将刁的设想“画出来”的关键任务，是推动下一阶段讨论的核心角色。

总而言之，这场会议成功地将一个模糊的概念冲突，转变成了两条清晰但互不相容的路线之争，并将最终决策的压力推向了顶峰。
