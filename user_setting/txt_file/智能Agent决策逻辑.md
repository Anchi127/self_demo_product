# 总Agent跨模块交互设计方案

## 1. 核心愿景：极致的无摩擦体验

在理想状态下，总Agent应该是一个无缝的智能助理，不被UI的模块化所束缚，能够直接领会并执行用户的跨模块任务。这能最大程度地保护用户的“心流”，让用户在不跳出当前工作上下文的情况下，高效完成其他领域的任务，从而提供一个真正强大和智能的AI原生体验。

## 2. 面临的挑战：上下文冲突与交互一致性

该愿景面临的核心挑战是：当一个跨模块任务需要用户进行深度交互（如填写复杂表单）时，如何在不破坏界面交互一致性的前提下完成任务。

**冲突场景示例：**
1. 用户当前在 **“资产”** 模块。
2. LUI接收到指令：“帮我创建一个新的谷歌营销活动”。
3. **问题：** “创建营销活动”的表单应该在哪里展示？
    * **错误做法：** 直接在第四栏（GUI区域）展示该表单。这会导致第四栏的GUI内容与第二、三栏的LUI及结果树（仍然是“资产”上下文）不匹配，从而破坏用户界面的核心逻辑和一致性，使用户感到困惑。

## 3. 最终方案：具备决策能力的智能总Agent

为了兼顾“无摩擦的体验”和“交互逻辑的一致性”，总Agent需要具备智能决策能力，根据任务的复杂度来动态选择最佳交互策略。

### 策略A：对于“即发即忘”(Fire-and-Forget)的简单跨模块任务

- **定义：** 指令本身已包含所有必要信息，执行过程无需用户额外交互。
- **场景举例：**
  - “暂停‘夏季促销’营销活动。”
  - “把‘加州地区’广告系列的预算提高10%。”
  - “删除我上次生成的那份数据报告。”
- **交互策略：采用无缝方案**
  1. 总Agent在后台直接调用对应的子Agent完成任务。
  2. 操作完成后，仅在LUI中返回一个简洁的文本确认信息（如：“操作已完成”）。
  3. （可选）在确认信息卡片上提供一个“查看详情”的链接，用户点击后，系统再执行完整的模块切换，跳转至对应模块的详情页面。

### 策略B：对于需要“深度交互”的复杂跨模块任务

- **定义：** 任务需要用户通过GUI填写表单、进行多步选择或复杂配置。
- **场景举例：**
  - “我要创建一个新的营销活动。”
  - “帮我申请一次复杂的账户操作。”
- **交互策略：采用“请求切换”方案**
  1. 总Agent在理解用户意图后，判断出该任务需要深度交互。
  2. LUI主动、礼貌地向用户发起上下文切换请求。
  3. **话术示例：** “好的，创建一个新的营销活动需要您提供一些详细信息。**是否现在为您切换到‘营销’模块以继续？**”
  4. 用户同意后，系统执行完整的模块切换（侧导航栏、LUI、结果树、GUI全部切换至“营销”模块），并在GUI中呈现相应的表单或操作界面。

### 结论

该“智能决策”方案，通过赋予总Agent判断任务复杂度的能力，实现了两全其美：
- **保障简单任务的极致效率和流畅感。**
- **保障复杂任务的逻辑清晰和界面一致性。**

这既保留了AI原生应用的智能与强大，又避免了用户因界面逻辑不一致而产生的混乱与挫败感，是V1阶段一个成熟且可落地的设计方案。
