# 成员与权限功能分析报告 (V2 - 系统发送邀请)

本报告基于对 `user_setting` 项目原型代码的分析，并根据**系统自动发送邀请**的新需求进行修订，旨在为撰写产品需求文档（PRD）提供依据。

---

## 第一部分：成员邀请流程分析 (基于 `InviteMemberDialog.tsx` 的修改)

此功能允许授权用户（如“项目负责人”或“管理员”）邀请新成员加入项目。

**1. 核心功能：**
管理员在界面完成邀请配置后，**由系统直接向被邀请人的邮箱或手机号发送包含唯一链接的邀请**。用户点击链接后根据引导完成注册或登录，即可加入项目。

**2. 邀请表单与业务逻辑：**

*   **邀请账号 (`Invite Accounts`):**
    *   输入方式：一个文本域，支持批量输入，最多 20 人。
    *   账号格式：支持中国大陆手机号或电子邮箱，通过换行或逗号分隔。
    *   格式验证：系统会校验输入的账号格式是否正确，并对无效格式进行提示。

*   **设置角色 (`Set Role`):**
    *   输入方式：一个下拉菜单，用于为被邀请者预设角色。
    *   可选角色：`管理员 (Admin)`、`财务 (Finance)`、`成员 (Member)`。
    *   权限约束：不能在邀请时直接将成员设置为 `项目负责人 (Owner)`。

*   **配置资产 (`Configure Assets`):**
    *   此部分逻辑保持不变，用于分配广告账户的访问权限。
    *   `财务`角色无需配置。
    *   支持`分配全部账户`或`分配部分账户`。
    *   支持`自动拥有自己申请开户的账户权限`开关。

**3. 发送邀请与结果展示：**
*   填写完表单后，点击**“发送邀请”**按钮。
*   **前置校验：** 逻辑不变，系统校验角色和资产配置是否合理。
*   **邀请发送：** 系统在后台为每个有效的被邀请者生成唯一的、有有效期的邀请链接，并**直接通过邮件或短信服务将邀请发送至对应的账号**。
*   **结果展示：**
    *   界面不再显示具体的邀请链接和“复制”按钮。
    *   改为显示一个确认页面或提示，告知管理员哪些账号的邀请已成功发送，哪些因格式错误等原因发送失败。
*   **最终操作：** 用户在结果页点击“完成”关闭弹窗。

## 第二部分：成员管理与权限体系分析 (基于 `MemberManagement.tsx` 及相关组件的修改)

此模块是整个成员与权限管理的枢纽。

**1. 主视图：**
*   UI和标签页 `成员列表`、`待接受邀请` 保持不变。

**2. 成员列表 (`Members List`):**
*   功能保持不变。

**3. 待接受邀请 (`Pending Invitations`):**
*   **信息展示：** 列表形式展示邀请的 `被邀请人账号`、`邀请人`、`预设角色`、`邀请时间`、`过期时间` 和 `邀请状态` (如：待接受、已过期、已撤销)。
*   **邀请操作 (重点变更):**
    *   **移除“复制”功能：** 由于链接由系统发送，管理员无需手动复制。
    *   **`撤销`:** 功能保留，使一条有效的邀请链接立即失效。
    *   **`重新发送`:** 功能保留，为一条邀请（尤其是已过期的）重新生成链接和有效期，并由系统再次发送。
    *   **`批量重新发送`:** **(新增)** 提供一个多选框和“批量重新发送”按钮，允许管理员一次性选择多个已过期的邀请并重新发送。

**4. 角色与权限体系 (`Roles and Permissions`):**
*   角色定义保持不变。

## 总结 (供PRD参考) - V2版

1.  **角色体系：** 系统采用“项目负责人 → 管理员 → 财务/成员”的四级固定角色体系，权限逐级递减。

2.  **成员邀请流程 (已更新):** 采用**“系统直邀”**模式，流程为 `输入账号 -> 设定角色 -> 配置资产 -> 确认信息 -> 系统自动发送邀请`。管理员不再需要手动复制和发送链接，提升了效率和规范性。

3.  **成员列表管理：**
    *   提供清晰的表格视图，展示所有已加入成员的 `用户名`、`账号`、`角色`、`账户数` 和 `加入时间`。
    *   授权用户可通过列表直接执行 `编辑`、`转移负责人权限`、`移除` 等操作。

4.  **待接受邀请管理 (已更新):**
    *   独立的标签页展示所有已发出但尚未接受的邀请。
    *   移除了链接复制功能，强调**管理操作**。
    *   核心操作为 `撤销`、`重新发送`，并新增 `批量重新发送` 功能，方便处理大量过期邀请。

5.  **权限管理与分配：**
    *   权限的分配与角色强绑定，并通过精细的权限矩阵进行管理。
