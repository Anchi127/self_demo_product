## 🔐 三、权限配置模块交互说明

### 3.1 模块概览

**入口路径：** `导航栏 → 系统与管理 → 权限配置`

**页面结构布局：**

`权限配置 [返回系统与管理]`

`[Adv层角色定义说明] [权限矩阵切换 Tab] [成员管理 Tab]`

### 3.2 Adv 层角色定义（修订版）

该定义适用于广告主（Adv）层面的权限控制。

| 角色 | 角色优先级 | 核心权限说明 |
|------|----------|--------------|
| **Owner** | **最高** | 广告主最高权限。可邀请成员、分配角色、分配广告账户、发起充值与管理钱包、转移所有权。 |
| **Admin** | **高** | 管理者。可邀请成员（Owner除外）、分配账户权限、编辑广告、发起投放。 |
| **Finance** | **中** | 财务角色。仅处理钱包、账务、对账相关功能。 |
| **Member** | **低** | 普通成员。仅能操作被分配的广告账户，不可访问钱包、不可邀请他人。 |

### 3.3 权限矩阵（简洁版）

| 功能 / 权限项 | Owner | Admin | Finance | Member | 权限限制说明 |
|----------------|--------|--------|----------|---------|---------------|
| 邀请成员 | ✅ | ✅ | ❌ | ❌ | Admin不能邀请Owner角色。 |
| 分配/修改成员角色 | ✅ | ✅ | ❌ | ❌ | Admin不能分配Owner角色。 |
| 分配广告账户 | ✅ | ✅ | ❌ | ❌ | Member角色仅能操作被分配的账户。 |
| 转移/交接 Owner | ✅ | ❌ | ❌ | ❌ | |
| 管理广告账户 | ✅ | ✅ | ❌ | ❌ | Admin/Member基于被授权的账户。 |
| 发起充值 / 使用钱包 | ✅ | ✅ | ✅ | ❌ | Admin/Finance基于授权的钱包。 |
| 查看钱包余额/流水 | ✅ | ✅ | ✅ | ❌ | Admin/Finance基于授权的钱包。 |
| 查看广告数据 | ✅ | ✅ | ✅ | ✅ | Finance仅查看消费类数据；Member仅看被分配账户数据。 |
| 编辑广告内容 / 发起投放 | ✅ | ✅ | ❌ | ✅ | 基于账户授权。 |
| 查看账单 / 下载发票 | ✅ | ✅ | ✅ | ✅ | Member受限。 |
| 管理权限配置 | ✅ | ❌ | ❌ | ❌ | |
| 审计日志查看 | ✅ | ✅ | ✅ | ✅ | 基于自身权限范围查看日志。 |

### 3.4 成员管理交互流程

#### 页面入口
`导航 → 广告与账户 → 选择广告主（Adv） → Tab【成员管理】`

#### 页面结构

`广告主名称（Adv: A001） [邀请成员]`

**成员列表（表格）：**

| 用户名 | 邮箱 | 角色 | 账户数 | 操作 |
|--------|------|------|--------|--------|
| 王一 | w1@xx.com | Owner | 全部账户 | [编辑] |
| 李二 | l2@xx.com | Admin | 2个账户 | [编辑] [移除] |
| 张三 | z3@xx.com | Member | 1个账户 | [编辑] [移除] |

### 3.5 关键操作交互

| 操作 | 触发者 | 结果 |
|------|----------|-------|
| **邀请成员** | Owner / Admin | 打开邀请弹窗，创建 invitation 记录，发送邮件通知。 |
| **分配角色** | Owner / Admin | 更新 `user_adv_role` 记录。 |
| **分配账户权限** | Owner / Admin | 更新 `user_account` 映射。 |
| **移除成员** | Owner / Admin | 弹窗确认后移除成员，立即失去访问权限。 |
| **转移 Owner** | Owner | 选择成员目标 → 验证 → 更新 `adv.owner_id`。 |

### 3.6 邀请成员弹窗

**字段配置：**
* 邮箱（支持批量输入）
* 角色下拉框（Owner / Admin / Finance / Member）
* 可访问广告账户（多选，Finance 不可选）
* 邀请有效期（默认 7 天）
* 自定义邀请消息（可选）

**前端提示/校验：**
* 若邮箱已存在且属于其他组织（org） → 提示并阻止或需确认跨 org。
* 若邮箱已是当前 Adv 成员 → 弹警告“该用户已存在”。

### 3.7 编辑成员弹窗

**功能说明：**
* 显示当前角色，允许修改角色（受权限控制）。
* 允许调整“可访问账户”多选框。
* 保存/取消按钮。

**规则限制：**
* 仅 Owner / Admin 可触发修改。
* Admin 不可将角色升为 Owner。
* 若角色修改为 Finance，系统自动移除其广告账户访问权限。

### 3.8 账户分配交互

**入口：** `成员管理 → 成员行 → [分配账户]` 或 `编辑成员弹窗中多选账户`。

**交互逻辑：**
* 展示该 Adv 下所有账户（包含媒体、名称、状态等信息）。
* 用户进行勾选后保存，系统更新 `user_account` 映射表。

**权限过滤逻辑：**
* Member 角色仅能查看和操作其被分配的账户数据。
* Admin 角色默认可查看全部账户（界面可标记为“全部账户”）。

### 3.9 转移 Owner 权限

**入口：** `成员管理 → Owner 成员行 → [转让所有权]`

**关键验证与结果：**
* 目标成员：必须选择现有成员（Admin/Member）。
* 二次验证：要求进行密码或 MFA 验证。
* 结果：转移成功后，原 Owner 角色自动降为 Admin。

### 3.10 典型使用场景

1.  **Owner 邀请新成员**
    * 操作：填邮箱、选 Admin、勾选 2 个账户 → 发送邀请。
    * 结果：系统发送邮件，受邀人登录后绑定该 Adv。
2.  **Admin 调整成员访问账户**
    * 操作：编辑成员 → 调整“可访问账户”多选框 → 保存。
    * 结果：权限即时生效。
3.  **Owner 转让权限**
    * 操作：选择新 Owner 成员 → 完成二次验证 → 确认转移。
    * 结果：所有权转移完成，原 Owner 自动降为 Admin 角色。
4.  **多广告主（multi-adv）场景**
    * 用户可在多个 Adv 下拥有不同角色。
    * 用户在切换 Adv 时，系统使用对应角色的权限进行判断。

| 状态 | UI 表现 |
|------|----------|
